Generation options
What each switch adds to the generated Dart, and when you want it on.
fromJson JSON → Dart

Adds a RootModel.fromJson(Map<String, dynamic> json) named constructor — the deserialise direction.

When enabled
Every field gets read out of the decoded map and cast to its inferred Dart type. Nested objects call their own fromJson; lists of objects are mapped item by item.
Turn it on
Whenever you receive this shape from an API, a file, or local storage and need real Dart objects.
Turn it off
If the model is only ever sent to the server, so you don't ship a constructor nothing calls.
// generated for you
RootModel.fromJson(Map<String, dynamic> json) {
  id = json['id'] as int?;
  address = json['address'] != null
      ? Address.fromJson(json['address'])
      : null;
}

// how you use it
final model = RootModel.fromJson(jsonDecode(body));
toJson Dart → JSON

Adds a Map<String, dynamic> toJson() method — the serialise direction.

When enabled
The object turns back into a plain map using your original JSON key names, not the Dart field names. Nested models get .toJson() called on them; lists of models are mapped.
Turn it on
When you POST or PUT this model, cache it, or write it to disk — anything that ends in jsonEncode.
Turn it off
For read-only response models you never send back.
// generated for you
Map<String, dynamic> toJson() {
  return {
    'id': id,
    'address': address?.toJson(),
  };
}

// how you use it
await http.post(url, body: jsonEncode(model.toJson()));
Prefix Naming

Puts a string of your choice in front of the class names this tool invents for you.

When enabled
A second field appears for the prefix. With Api, the nested class discovered from "address" is generated as ApiAddress instead of Address — and every reference to it updates to match.
Turn it on
When the generated names would collide with classes you already have — User, Address and Item are the usual suspects — or to namespace models per API.
Scope
The prefix applies to the nested classes discovered in your payload. The root class always uses exactly what you typed in Class.
// prefix off
Address? address;

// prefix "Api"
ApiAddress? address;
